# HoribaBridge

`HoribaBridge.exe` owns the legacy 32-bit JYMono COM object on a WinForms STA
thread. Python communicates with it through newline-delimited JSON on standard
input/output. This avoids both the Python COM activation hang and the
`pythonnet` dependency.

## Build

Run from PowerShell:

```powershell
Set-Location C:\Users\LEC\Desktop\Fede\HoribaBridge
.\build.ps1
```

The script deliberately calls the installed .NET Framework 4 compiler, rather
than `dotnet build`; it uses the interop assemblies already generated by the
official sample. Its output is x86.

## Python use

```python
from horiba import Horiba

with Horiba() as h:
    h.connect("Mono1")
    print(h.wavelength())
    # h.move_wavelength(500.0)  # executes a real instrument movement
```

Only call a move method once the optical path and experiment are safe. Valid
slit locations are the SDK names `Front_Entrance`, `Front_Exit`,
`Side_Entrance`, and `Side_Exit`.

`connect()` responds to the asynchronous SDK Initialize event and waits for
`state="ready"`; it does not assume that `Initialize()` completed synchronously.
The Python client uses the local Windows ANSI encoding for bridge messages,
because the legacy SDK can include non-UTF-8 text in an exception message.
